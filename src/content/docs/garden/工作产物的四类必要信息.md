---> 一个能够被接手、复用和持续完善的工作产物，至少应回答四个问题：**现在采用什么结论、凭什么相信、为什么发生变化、下一步从哪里继续。**

来源：2026-10-21 关于 Skill 交付产物与后续产品设计的对话。以下四类信息由助手在讨论中提炼，用户认为有价值并要求保存；这是待实践完善的工作方法建议。

## 适用范围

这里的“产品”可以是一份候选人名单、研究报告、方案或决策记录。对于需要交接、复盘、复用或迭代的工作，除了最终结果，还应保留理解和继续推进结果所需的信息。记录深度随工作价值与复杂度调整，简单任务可以只用几行。

## 四类必要信息

### 一、当前有效结论

说明**现在以什么为准，以及在什么条件下成立**。

- 当前采用的结论、方案、判断或标准。
- 适用对象、范围、约束与有效时间；尚未确定的内容明确标注。
- 当前版本或更新时间，使接手者能快速找到正在使用的结果。

价值：让人和 Agent 不必从历史对话中猜测哪一个版本仍然有效。

### 二、支持结论的证据

说明**这个结论依据什么形成，证据能否重新核查**。

- 支持关键结论的资料、观察、反馈或验证结果，以及可追溯的来源。
- 资料的日期或采集时间；会过时的事实需要保留时间边界。
- 区分已确认事实、推断与待核实信息，并保留与结论冲突的证据。

价值：后续使用者可以检查判断依据，在新信息出现时重新评估。

### 三、版本与变化原因

说明**结论怎样从旧版本变成当前版本，为什么改变**。

- 旧结论 → 新结论，以及发生变化的时间。
- 哪些证据、反馈、失败尝试或踩过的坑触发了修订。
- 分开记录**对象事实变化**与**判断标准变化**；两者同时发生时分别说明。

例如，某方案从“不接受”变为“接受”，可能是方案成本下降，也可能是允许的预算上限提高。前者是事实变化，后者是标准变化，两种经验的复用条件不同。

价值：保留能够解释结果的关键历史，让后来者知道哪些经验可沿用、哪些前提已经改变。

### 四、下一步与未完成项

说明**工作停在哪里，下一位接手者如何继续**。

- 尚缺的证据、未解的问题、待验证的假设。
- 建议补齐的方法、可继续推进的位置，以及重新判断的触发条件。
- 已确认的行动与建议行动分别标明；负责人、期限或完成状态未知时保留“待确认”。

价值：下一轮工作可以从明确的断点继续，避免重复摸索。

## 可直接复用的模板

```markdown
## 1. 当前有效结论
- 当前结论 / 采用方案：
- 适用范围与关键约束：
- 版本 / 更新时间：

## 2. 支持结论的证据
- 关键证据、来源与日期：
- 已确认事实：
- 推断、冲突证据与待核实内容：

## 3. 版本与变化原因
- 修订日期：
- 旧结论 → 新结论：
- 对象事实变化：
- 判断标准变化：
- 修订依据 / 失败尝试 / 踩坑经验：

## 4. 下一步与未完成项
- 缺口 / 未解问题：
- 继续推进的方法与位置：
- 需要重新评估的触发条件：
- 已确认行动 / 建议行动（分别注明，未确认信息留空）：
```

## 如何持续完善

每次复用时，先核对当前结论的适用条件，再检查证据是否仍然有效；出现新的证据或标准调整时，更新结论、保留旧版本并补写变化原因，最后同步未完成项。这样，结果和形成结果的经验可以一起积累。

仍需通过实际工作验证：这四类信息是否足以支持他人接手，以及维护成本是否与复用价值相称。
